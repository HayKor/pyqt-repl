# План 004 — Этап 4: Основные команды (вариант №4)

> Выполняется после мёржа этапа 3 в `main`, на ветке `feat/commands` от свежего `main`.
> Перед началом сверить интерфейсы с фактическим кодом этапа 3 (`core/vfs.py`,
> `CommandContext`) — план опирается на `docs/plans/003_stage3_vfs.md`.

## Цель

Реальная логика `ls` и `cd` поверх VFS, новые команды `cat` и `tac`, приглашение с
текущим каталогом VFS.

## Требования этапа → как закрываем

| # | Требование | Реализация |
|---|------------|------------|
| 1 | Логика `ls`, `cd` | Работают с `ctx.vfs` / `ctx.cwd` через `VFS.resolve`/`normalize` |
| 2 | Новые команды `cat`, `tac` | Классы команд в `REGISTRY` |
| 3 | Стартовый скрипт со всеми режимами команд, VFS и ошибками | `scripts/startup/stage4.repl` + скрипты ошибок (скрипт прерывается на первой ошибке) + `scripts/stage4.sh` |
| 4 | Коммит | `feat(commands): ...` на ветке `feat/commands` |

## 1. Средства

Чистый Python поверх модели VFS этапа 3; `stat.filemode` (stdlib) для строки прав
`drwxr-xr-x` (передавать `stat.S_IFDIR | mode` / `stat.S_IFREG | mode`). Команды
по-прежнему без Qt.

## 2. Поведение команд

Общее: опции разбираются как на этапе 1 (`-la` = `-l -a`; `--` не поддерживаем);
неизвестная опция → `CommandArgsError("<cmd>: invalid option -- 'x'")` (код 2). Ошибки
по отдельным путям не прерывают обработку остальных аргументов: вывод копится в
`output`, сообщения — в `error`, итоговый код 1 (для `ls` — 2, как в GNU), если была
хоть одна ошибка. Вывод без завершающего `\n` (виджет добавляет перевод строки сам).

### `ls [-a] [-l] [-h] [PATH...]`
- Без путей — `ctx.cwd`. Имена сортируются по возрастанию (`sorted`, байтово).
- Скрытые (`.`-начинающиеся) показываются только с `-a`; с `-a` также `.` и `..`.
- Короткий формат — имена через два пробела в одну строку (без раскладки по колонкам);
  каталоги без суффиксов.
- `-l` — по строке на элемент: `drwxr-xr-x user user  4096 name`; поля выровнены по
  ширине (owner, group, size); размер каталога — 4096, файла — `len(data)`; перед
  списком каталога строка `total N` (N — число элементов, упрощение; задокументировать).
  Даты нет — в модели VFS нет времени (задокументировать).
- `-h` — только вместе с `-l`: размеры `1.5K`, `12M` (как GNU: одна цифра после
  точки для < 10, округление вверх). Без `-l` игнорируется.
- Путь-файл → выводится сам файл (в `-l` — его строка).
- Несколько путей: сначала файлы, затем каталоги с заголовками `path:` и пустой строкой
  между блоками (как GNU).
- Ошибка: `ls: cannot access 'x': No such file or directory` / `Not a directory`,
  код 2.

### `cd [DIR]`
- Без аргумента — в корень VFS `/` (реальный `$HOME` обычно отсутствует в VFS;
  задокументировать). `cd ~` раскрывается парсером в реальный `$HOME` → обычно ошибка,
  это ожидаемо.
- `cd -` → предыдущий каталог (`ctx.oldpwd`, добавить в контекст/Shell) и печать нового
  пути, как в bash; если предыдущего нет — `cd: OLDPWD not set`, код 1.
- Ошибки: `cd: x: No such file or directory`, `cd: x: Not a directory` (код 1),
  `cd: too many arguments` (код 2 через CommandArgsError, как сейчас — оставить).
- Меняет `ctx.cwd` (канонический путь из `normalize`).

### `cat [-n] FILE...`
- Конкатенация содержимого; байты декодируются `utf-8` с `errors="replace"`.
- `-n` — нумерация всех строк сквозная через все файлы, формат GNU `%6d\t%s`.
- Без файлов → `cat: missing file operand` (стандартного ввода у эмулятора нет;
  задокументировать), код 2 через CommandArgsError.
- Каталог → `cat: x: Is a directory`; нет файла → `cat: x: No such file or directory`;
  код 1, остальные файлы выводятся.
- Если итог заканчивается на `\n` — убрать один завершающий `\n`.

### `tac FILE...`
- Для каждого файла по очереди: строки файла в обратном порядке (как GNU tac с
  разделителем `\n`: последняя строка без `\n` приклеивается — повторить поведение GNU:
  `printf 'a\nb' | tac` → `ba\n`). Результаты файлов идут в порядке аргументов.
- Опций нет: любая `-x` → invalid option. Без файлов → `tac: missing file operand`.
- Ошибки как у `cat` (`tac: x: ...`), код 1.

### Приглашение
`MainWindow` после каждой команды (интерактивной и из скрипта) обновляет prompt:
`user@host:<cwd>$ ` (`/` для корня). Эхо команды использует приглашение, актуальное
на момент ввода.


скрипты прошлых этапов, которые на него опираются, обновить (скрипты этапов 2–3 должны
продолжать работать).
